# Курсы, LM Studio и JPlag

## Кабинеты и статистика

Раздел **Курсы** содержит карточки с прогрессом. Внутри курса студент видит задания, сроки, последнюю попытку, статус и подтверждённые баллы. Кнопка у задания открывает сдачу PR или результат. Эксперт и ревьюер видят ведомость по заданиям, матрицу потока и вкладку **Успеваемость**: график «итоговый балл — дни относительно дедлайна», распределение статусов и слабые критерии.

На каждую пару «студент, задание» учитывается **последняя попытка**. Знаменатель прогресса — число заданий × число активных зачисленных студентов (для студента — только его задания). Студенты без отправок тоже входят в статистику. Выполнено означает подтверждённую проверку; графики оценок используют только её итоговые баллы. Новая отправка снова переводит задание в проверку.

«Что заметил агент» собирается из результатов критериев и AI-замечаний. Студенту черновики не выдаются. Эксперт видит только свои курсы. Ревьюер видит статистику назначенного потока, но обычное ревью открывает только при назначении на него.

## LM Studio

В корневом `.env`:

```dotenv
LLM_PROVIDER=lm_studio
LM_STUDIO_BASE_URL=http://127.0.0.1:8002/v1
LM_STUDIO_MODEL=openai/gpt-oss-20b
LM_STUDIO_API_KEY=
```

Включите **LM Studio → Developer → Start Server**, порт **8002**, и загрузите модель. Идентификатор модели должен совпадать с `/v1/models`. Если включена аутентификация LM Studio, укажите токен в `LM_STUDIO_API_KEY`; иначе оставьте пустым. Google/OpenAI ключи для локального сервера не требуются.

Для существующей локальной базы:

```bash
npm run model:local
```

Команда сохраняет профиль в `.env` и обновляет endpoint `openai-default`, сохраняя привязки заданий. Затем перезапустите `npm run dev`. Остальные endpoints не изменяются. После создания базы модели хранятся в каталоге **Модели и настройки**: изменение одного `.env` не переписывает каталог при каждом старте. Кнопка **Проверить** проверяет соединение; генерация выполняется при проверке работы.

Для текущего GPT OSS в LM Studio используется JSON по инструкции: схема передаётся в промпте, а backend проверяет ответ и повторяет запрос при ошибке структуры. Объяснение корректного отказа от оценки сохраняется. Принудительный JSON Schema в этой локальной конфигурации превышал таймаут, поэтому в профиле он отключён.

Контекст в каталоге по умолчанию 32 000 токенов, лимит ответа 4 000, таймаут 180 секунд. Согласуйте контекст с параметрами загрузки модели в LM Studio. Если модель отвечает дольше — увеличьте таймаут в каталоге.

В Docker адрес машины-хоста — `http://host.docker.internal:8002/v1` (Compose использует его для новой базы). Для уже существующей Docker-базы обновите Base URL в каталоге. LM Studio должен принимать соединения контейнера. Облачный backend не сможет обратиться к ноутбуку через `127.0.0.1`.

Документация: [OpenAI-совместимый API LM Studio](https://lmstudio.ai/docs/developer/openai-compat).

## JPlag

```bash
npm run setup:jplag
```

Скрипт скачивает официальный JPlag **6.3.0**, проверяет SHA-256 и устанавливает Java 25 в `backend/vendor`. Системная Java не меняется. Поддержаны macOS/Linux, ARM64 и x64. Docker-образ включает JPlag и Java. Для ручной установки: `JPLAG_JAR` и `JPLAG_JAVA` — абсолютные пути к JAR и Java. Временные каталоги внутри `backend/similarity-data` удаляются после сравнения. `JPLAG_TIMEOUT_SECONDS` по умолчанию 120, максимум 600 секунд.

Откройте **Курсы → курс → Сходство кода**, выберите задание и язык, нажмите **Сравнить решения**. История сохраняется в базе. Сравниваются последние отправки разных активных студентов одного задания и потока. Нужно дождаться окончания загрузки работ; для запуска нужны минимум две работы с кодом выбранного языка.

Результат содержит средний и максимальный проценты сходства, совпавшие строки и исходные фрагменты. Используются токены выбранного языка: переименование переменных само по себе не скрывает сходство. Процент **не является вероятностью списывания**. Общий стартовый код также может давать совпадения; в этой интеграции базовый шаблон автоматически не исключается. Неполные снимки PR и демонстрационные работы помечены отдельно. Лимит запуска: 200 решений и 100 МБ исходников. Неподдерживаемые файлы исключаются. Код студентов не исполняется и не отправляется во внешние API.

Эксперт и ревьюер назначенного потока видят пары и фрагменты. Решения:

- **Ожидает решения** — внутренний сигнал.
- **Обсудить совпадения со студентами** — обязателен комментарий. Только этот текст появится у обоих участников в их курсах, без чужого кода и процентов.
- **Совпадение объяснено** — внутренний комментарий, студентам не показывается.

Запуск JPlag и решение по паре **не меняют оценку и не назначают штраф**. Решение и автор сохраняются в аудите. Модуль выявления использования ИИ остаётся заглушкой и не связан с JPlag.

Источники: [JPlag](https://github.com/jplag/JPlag), [релиз 6.3.0](https://github.com/jplag/JPlag/releases/tag/v6.3.0).

## Категории замечаний

В рабочем пространстве ревью код подсвечивается по категории: логика — красный, требования — фиолетовый, качество — жёлтый, вопросы — синий, сильные стороны — зелёный. Выделите код мышью или строки с Shift, выберите категорию в появившейся панели и добавьте комментарий. Подсветка охватывает весь диапазон; цветные точки показывают пересекающиеся категории. Отклонённые замечания не подсвечиваются. Смена категории в редактировании заметки сохраняется на сервере.
